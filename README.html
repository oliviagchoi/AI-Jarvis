Jarvis Assistant Project Idea

Author

Nav Sanya Anand

This folder documents the current project idea and the working system flow for the Jarvis Assistant so far.

One-Line Idea

Jarvis is an emotion-aware voice assistant that accepts text or speech, detects the user’s emotional state, gives the language model emotional guidance, stores recent conversation context, and returns both a text reply and a synthesized voice artifact.

Current Product Shape

  • Frontend: browser console at /ui with text chat, manual voice turns, wake phrase support, wellness demo inputs, emotion monitor, conversation history, and audio playback.
  • Backend: FastAPI service with REST endpoints for chat, voice upload, history, and health checks.
  • Orchestration: AssistantOrchestrator coordinates transcription, emotion detection, memory, LLM response generation, and text-to-speech output.
  • Memory: recent turns are stored as ConversationTurn rows with role, content, session id, emotion, and timestamp.
  • Database: MySQL is the primary configured database; SQLite is used as a fallback when MySQL is unavailable.

Emotion Set

Jarvis uses emotions in three places: detection, LLM tone guidance, and frontend visual state.

Emotion How It Can Be Detected LLM Response Guidance UI Treatment
neutral Fallback state, neutral audio, no text keyword hit, SenseVoice neutral or emo_unk Concise, helpful, emotionally steady Neutral baseline
calm Audio model label Relaxed, confident, smooth pacing Calm visual state
happy Audio labels like joy/happiness/happy, positive text keywords, SenseVoice happy Upbeat, clear, positive, still concise Happy visual state
excited Possible audio label or frontend state; text word excited currently maps into happy Upbeat and clear when passed through as detected emotion Excited visual state
surprised Audio labels surprise/surprised, SenseVoice surprised Upbeat and clear Surprised visual state
sad Audio labels sad/sadness, sad text keywords, SenseVoice sad Warm, gentle, validating, with a small practical action Sad visual state
fear Audio labels fear/fearful, stress/anxiety text keywords, SenseVoice fearful or fear Grounded, reassuring, lower energy, one or two stabilizing next steps Labeled as stressed/anxious
angry Audio labels anger/angry, angry text keywords, SenseVoice angry Calm, de-escalating, respectful, solution-oriented Angry visual state
disgust SenseVoice disgusted tag Falls back to the default LLM guidance unless specific guidance is added Currently falls back to neutral UI styling

Text Emotion Keywords

The local keyword detector currently checks these emotion groups:

  • happy: happy, excited, great, awesome, good, glad, love, amazing, fantastic, wonderful
  • sad: sad, upset, frustrated, depressed, down, tired, hurt, cry, lonely, hopeless
  • angry: angry, mad, furious, annoyed, irritated, hate
  • fear: afraid, scared, nervous, worried, anxious, panic, overwhelmed, stressed, stress, tense

Hybrid Emotion Decision Rules

In legacy voice mode, Jarvis combines audio emotion and transcript keyword emotion:

  1. Start with the audio classifier result.
  2. If no text emotion is found, keep audio emotion or fall back to neutral.
  3. If audio confidence is below 0.55, use the text emotion.
  4. If audio is neutral or calm and text confidence is at least 0.45, use the text emotion.
  5. If audio and text disagree, use text only when text confidence is at least 0.12 higher than audio confidence.
  6. Otherwise keep the audio emotion.

Prompt Context Sent To The LLM

The LLM receives the rendered prompts/jarvis_chat.txt template. The context payload contains:

  • detected_emotion
  • emotion_guidance
  • recent conversation_history
  • optional wellness_signal

The prompt instructs Jarvis to be calm, concise, practical, easy to say out loud, emotion-aware, supportive during distress, and careful not to invent personal facts.

Project Status So Far

  • Working backend app factory and FastAPI routes are in place.
  • Browser UI supports text, voice recording, wake phrase listening, playback speed, emotion display, raw JSON diagnostics, and history.
  • Bedrock is the current LLM provider in .env.
  • Legacy voice mode is active: Whisper plus hybrid emotion detection.
  • SenseVoice is implemented but currently disabled by configuration.
  • TTS attempts Coqui synthesis and gracefully falls back to text output when Coqui is unavailable.
  • Conversation history is persisted per session and cleared on app startup.
